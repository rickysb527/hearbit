# 分割ロジックの決定事項

## 音声構造（HSK3級単語 / 001.mp3 で確認）

各ページ音声（約95秒）は以下の構造:

```
[冒頭アナウンス 約13秒]  ← 「第◯課」等のページ見出し
[単語1  約13秒]          ← 単語(中) → 日本語訳 → 例文1(中) → 例文2(中)
[単語2  約14秒]
...
[単語6]
```

- 単語は 6〜7語/ページ 程度
- **単語境界**: 2.0秒以上の無音
- **単語内ブロック境界**（単語→訳→例文）: 0.5〜1.7秒の無音

## アナウンスの扱い（汎用設計：ラベル方式）

### 背景
アナウンスには複数種類あり、出現位置は単語帳ごとに異なる:
- **品詞アナウンス**（「動詞」「副詞」等・数秒）: HSK3級では 21,33,34,40,41... のページ先頭
- **セクションアナウンス**（課の見出し等・長い）: HSK3級では 1,51,76 のページ先頭（001は約13秒）
- **なし**: それ以外のページ

音声特徴からアナウンスを機械判定するのは単語帳ごとにバラつき信頼性が低い。
そこで「自動除去」ではなく「**確実に分割 → 各セグメントにラベル付与 → 後から修正可能**」とする。

### 決定：ラベル方式
1. **分割は無音境界で機械的に行う**（確実）。1ページを複数セグメントに切る。
2. 各セグメントに `type` を付与:
   - `word`: 単語（単語→訳→例文2つ）
   - `announce`: アナウンス（品詞・見出し等）
3. `type` の初期値は簡単なヒューリスティックで自動判定（下記）。
4. 最終的にアプリ側で手動トグルして修正できる（どの単語帳でも破綻しない）。

### 自動判定ヒューリスティック（初期値用）
- ページ先頭セグメントが、そのページ内の他セグメント長の中央値より**極端に短い**（品詞アナウンスの疑い）
- または**極端に長い**（長い見出しが単語1に結合している疑い）
- 判定はあくまで初期値。正解データ `announce_pages.json` で精度を検証する。

### アプリ・まとめ音声での利用
- **アプリ再生**: `type: word` のセグメントのみ一覧表示。`announce` はスキップ/折りたたみ。
- **まとめ音声（50/100語）**: `type: word` のセグメントのみ結合。
- **長いアナウンスが単語1に結合しているページ**（001等）: そのセグメントを `word` のまま扱うが、
  まとめ音声用には「単語の発音部分だけ」を切り出す処理を将来追加する余地を残す。

## 分割パラメータ

| パラメータ | 値 |
|---|---|
| silencedetect noise | -30dB |
| silencedetect 最小無音長 | 0.4秒 |
| 単語境界の閾値 (WORD_GAP) | 2.0秒 |
| 分割点 | 単語境界となる無音区間の中点 |
| 短小結合の閾値 (SHORT_MERGE_RATIO) | 0.45（本体中央値の45%未満） |
| アナウンス低信頼の閾値 (ANNOUNCE_LOW_CONF) | 0.5秒 |
| RMS窓（JS版のみ） | 10ms |

## 後処理ルール（build_metadata.py で確定・検証済み）

分割は無音境界で機械的に行うが、2.0秒ちょうど付近の無音による誤爆と、アナウンス結合を
以下の後処理で補正する。**適用順は ②結合 → ①切り離し**（結合後の本体中央値を①で使うため）。

### ② 短小セグメント結合（例文分離の修正）
2.0秒ちょうど付近（実測2.00〜2.15秒）の無音が WORD_GAP=2.0 にギリギリ引っかかり、
本来「例文の間（単語内区切り）」なのに単語境界と誤判定されるページがある。結果、例文が
独立した極端に短いセグメントに分離する。
- **ルール**: 本体（index1以降）で「そのページ本体中央値の45%未満」のセグメントを例文分離と
  みなし、**直前セグメントに結合**して単語に戻す。結合したセグメントに `merged: true` を残す。
- **対象**: HSK3級では 050 / 095 / 096 / 098 の各1セグメントのみ（他ページ不変を検証済み）。
- 単純な閾値変更（2.0→2.15等）では正当な境界（003等・無音2.14〜2.15秒）を壊すため不可。
  無音長ではなく「短小セグメントの併合」で対処するのが安全。
- 先頭セグメント（アナウンス+単語1）が短くても対象外（アナウンス切り離しは①で別途扱う）。

### ① アナウンス切り離し（案①(a)中央値基準）
`has_announce`（type=word+announce）の先頭セグメントについて、②結合後の本体中央値を使い:
1. 先頭セグメント末尾から「本体中央値ぶん」遡った時刻を単語1開始の目安とする
2. 最も近い内部無音境界（0.4秒以上の中点）にスナップして境界を確定
3. 目安が先頭より前なら、先頭寄りの最初の内部境界にスナップ
- 結果を先頭セグメントに `announce_end`（秒・絶対時刻）で持たせる。
  - 単語1再生 = `announce_end`〜`end` / アナウンス部 = `start`〜`announce_end`
  - 既存の `start` / `end` / `type` は壊さない（後から手動修正可能）
- アナウンス長が0.5秒未満のページには `announce_low_confidence: true` を付与（実聴確認を促す）。
  HSK3級では 021 / 034 / 045 / 095 / 097 の5ページ（品詞アナウンスが極短で境界が先頭寄り）。
- **検証**: 案B（固定ブロック数逆算）は「1単語=4/2ブロック」前提が崩れ20/40で失敗。
  案①(a)中央値基準は39/40で単語1尺が本体と整合し安定。最小値基準(b)は外れ値に脆く不採用。

> いずれも機械判定は**初期値**。最終的な境界の正しさ（特に低信頼ページ）は人間の耳で確認し、
> メタデータ（`announce_end` / `merged` / `type`）で後から修正できる設計を維持する。

- **RMS窓=10ms** は JS版（Web Audio API, `app/js/splitter.js` の `WIN_MS`）専用のパラメータ。
  ffmpeg silencedetect のレベル判定を素のJSで再現するための計算窓。全98ページで
  Python版 segments.json とセグメント数・cut点（±0.15s）が 98/98 一致する値。
  Python版（ffmpeg）は内部フィルタで判定するため、この項目は関係しない。
